  `ai-studio-murafiq-cb988db3-5a07-40b7-b1ca-8eaaae894475`
- **القرار المعماري لجهات الاتصال**: تم اعتماد تخزين `contacts?: ClientContact[]` كمصفوفة مضمّنة محدودة السقف (حتى 25 جهة اتصال لكل عميل، عبر `MAX_CLIENT_CONTACTS = 25`) داخل وثيقة العميل نفسها للأسباب التالية:
  1. ينسجم بالكامل مع اشتراكات `subscribeClients` وذاكرة Offline-First الحالية دون فتح `N` اشتراك Firestore فرعي لكل عميل في القائمة.
  2. يتيح إنشاء وتعديل وتعيين جهة الاتصال الرئيسية دون إنترنت ومزامنتها ضمن آلية `OperationCoordinator` و`rejectedWrites` القائمة.

- **`lastContactAt`**: لا يتم تخزينه كحقل يدوي معرض للتقادم أو التناقض، بل يُشتق ديناميكيًا عبر `computeClientKpis` من أحدث اجتماع فعلي مسجل لا يتجاوز الوقت المرجعي (أو اجتماع منتهٍ).

## 3. احتساب مؤشرات العميل (KPIs) ودقة الحالة

تُشتق جميع الأرقام في `computeClientKpis` من السجلات الفعلية التابعة للعميل وحده (`clientId`):

- **إجمالي الاجتماعات**: عدد الاجتماعات ذات `clientId === client.id`.
- **الاجتماعات القادمة**: الاجتماعات غير المنتهية التي يقع `dateTime` الخاص بها في المستقبل (`>= referenceDate`).
- **المهام المفتوحة**: المهام التي حالتها `pending` أو `in_progress` فقط (مع استبعاد `completed` و`cancelled`).
- **المهام المتأخرة**: المهام المفتوحة التي لها `dueDate` يسبق تاريخ اليوم المرجعي (`dueMidnight < refMidnight`).
- **المهام المنجزة**: المهام ذات الحالة `completed`.
- **آخر نشاط مسجل**: أحدث حدث فعلي زمنيًا (`<= referenceDate`) عبر الاجتماعات، القرارات، المهام، والملاحظات.

كما يميز شريط الحالة والمؤشرات (`deriveClientSyncDisplayState`) بوضوح بين:
- جاري التحميل (`loading` عند عدم اكتمال تحميل المجموعات بعد، مع إظهار `—` بدلًا من ادعاء `0`)
- خطأ تحميل (`error`)
- رفض مزامنة (`failed` مع الإبقاء على المسودة)
- وضع عدم الاتصال أو التعديلات المعلقة محليًا (`offline_pending`)
- متزامن بالكامل (`synced`)

## 4. منطق التنبيهات الحتمية («ما الذي يستحق انتباهك؟»)

يعتمد قسم الانتباه في `evaluateClientAttentionAlerts` على قواعد حتمية صريحة وشفافة 100% (دون استدعاء Gemini وبدون أرقام صحة علاقة مصطنعة):

1. **`overdue_tasks`**: عند وجود مهام مفتوحة متأخرة عن `dueDate` -> تنبيه مع العدد الفعلي وإجراء مباشر لمراجعة المهام.
2. **`upcoming_meeting`**: عند وجود اجتماع قادم غير منتهٍ خلال 48 ساعة -> «لديك اجتماع مع هذا العميل اليوم/غداً/خلال 48 ساعة» مع زر فتح الاجتماع.
3. **`high_priority_tasks`**: عند وجود مهام مفتوحة بأولوية `urgent` أو `high` -> تنبيه متابعة الأولوية العالية.
4. **`stale_contact`**: عند مرور `>= 30` يوماً دون اجتماع/تواصل مسجل (أو منذ إضافة العميل إن لم تُسجل اجتماعات ومضى 30 يومًا) -> تنبيه هادئ مرفق بتوضيح إلزامي:
   *«مبني على الأنشطة المسجلة في التطبيق فقط ولا يُثبت عدم وجود تواصل خارجه.»*

الضمانات الحاكمة:
- لا يتم تغيير `relationshipStatus` تلقائيًا أبدًا.
- لا يتم إنشاء مهام أو اجتماعات تلقائيًا.
- حد أقصى تنبيه واحد لكل فئة لمنع التكرار المزعج.

## 5. التوافق مع Offline-First والأمان وعزل البيانات

- تم تحديث `firestore.rules` و`firebase-blueprint.json` محليًا فقط (دون تنفيذ `firebase deploy` وبانتظار مراجعة واعتماد مالك المنتج):
  - تبقى الحقول الإلزامية في `isValidClient` محصورة في `['id', 'name']` لضمان عدم كسر أي عميل قديم.
  - إضافة قائمة الحقول المسموحة الاختيارية مع تحقق صارم من الأنواع، القيم المسموحة (`relationshipStatus`, `importance`)، والأطوال والأسقف (`tags.size() <= 20`, `contacts.size() <= 25`).
  - بقاء العزل الكامل تحت `/users/{userId}/...` واستخدام القاعدة المسماة حصريًا.
  - عدم تخزين أو عرض أي روابط B2 مؤقتة أو مفاتيح وصول داخل بيانات العميل (يتم الانتقال عند طلب المرفقات إلى مساحة الاجتماع المحمية).
- جميع تعديلات العميل وجهات الاتصال والمهام والملاحظات تعمل عبر `OperationCoordinator` و`fbSave*` بسياسة Offline-First الكاملة مع تمييز العناصر المعلقة (`pendingDocIds`) والمرفوضة (`rejectedWrites`).
