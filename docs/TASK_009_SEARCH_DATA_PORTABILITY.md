## 1. نظرة عامة على نظام البحث الشامل («البحث الشامل»)

يوفر نظام **«البحث الشامل»** (`src/utils/searchEngine.ts` و`src/components/SearchModal.tsx`) تجربة بحث موحدة وفورية عبر جميع السجلات المحمّلة للمستخدم الحالي في الجلسة (`AuthenticatedSession`) دون إنشاء استعلامات Firestore إضافية لكل حرف يكتبه المستخدم.

يرتكز النظام على ثلاثة مبادئ:
1. **الوصول السريع والدقيق**: تطبيع النصوص العربية والأرقام وترتيب النتائج حتميًا حسب درجة التطابق، مع الانتقال المباشر إلى السجل الأصلي بضغطة واحدة.
2. **الشفافية والصدق التشغيلي**: الإفصاح الصريح إذا كانت بعض المجموعات لا تزال قيد التحميل، وعدم البحث داخل ملفات المرفقات الثنائية المخزنة في Backblaze B2.
3. **الأمان والعزل**: عزل كامل للبيانات حسب `currentUserId`، وتمييز النصوص المطابقة عبر عناصر React الآمنة (`<mark>`) دون استخدام `dangerouslySetInnerHTML`.

## 2. السجلات والحقول المشمولة في البحث

يبحث المحرك الموحد عبر **6 أنواع من السجلات**:

| نوع السجل (`recordType`) | الحقول الأساسية (Primary) | الحقول الثانوية والمرتبطة (Secondary / Related) | وجهة الانتقال المباشر |
|---|---|---|---|
| **العملاء (`client`)** | الاسم (`name`) | الشركة (`company`)، القطاع (`industry`)، الهاتف (`phone`)، البريد (`email`)، الوسوم (`tags`)، العنوان، الموقع، الملاحظات، والوصف، وجهات الاتصال المرتبطة | ملف العميل الشامل (Client 360) |
| **جهات الاتصال (`contact`)** | اسم جهة الاتصال (`contact.name`) | المنصب (`title`)، القسم (`department`)، الهاتف (`phone`)، البريد (`email`)، الملاحظات (`notes`)، واسم العميل والشركة الأم | ملف العميل الأم في Client 360 |
| **الاجتماعات (`meeting`)** | عنوان الاجتماع (`title`) | الملاحظات التقليدية (`notes`)، ملخص النقاش (`discussionSummary`)، بنود جدول الأعمال (`agendaItems.title` / `notes`)، القرارات (`decisions.text` / `ownerName`)، الملاحظات الإضافية (`minutesAdditionalNotes`)، الموقع، المشاركون، واسم العميل المرتبط | مساحة عمل الاجتماع مباشرة |
| **المهام (`task`)** | عنوان المهمة (`title`) | وصف المهمة (`description`)، اسم العميل المرتبط، وعنوان الفرصة المرتبطة (`opportunityTitle`) | نافذة تحرير/تفاصيل المهمة مباشرة |
| **الملاحظات (`note`)** | عنوان الملاحظة (`title`) | محتوى الملاحظة (`content`)، الوسوم (`tags`)، واسم العميل المرتبط | محرر الملاحظة في قسم التقارير والملاحظات |
| **فرص الأعمال (`opportunity`)** | عنوان الفرصة (`title`) | الوصف (`description`)، اسم العميل المرتبط، الإجراء القادم (`nextAction`)، نوع الفرصة (عربي/إنجليزي)، المرحلة (عربي/إنجليزي)، المصدر، وسبب الخسارة | تفاصيل الفرصة في مسار الفرص |

## 3. قواعد التطبيع العربي والرقمي (`normalizeArabicSearchText`)

يُطبّع النص لأغراض المقارنة فقط مع الحفاظ التام على النص الأصلي المخزن والمعروض للمستخدم:

1. **توحيد الألف والهمزات**: تحويل `أ`، `إ`، `آ`، `ٱ` إلى `ا` (مثال: `أحمد` يطابق `احمد`، و`إبراهيم` يطابق `ابراهيم`).
2. **توحيد التاء المربوطة والهاء**: تحويل `ة` إلى `ه` لأغراض المطابقة (مثال: `شركة المنارة` يطابق `شركه المناره`).
3. **توحيد الألف المقصورة والياء**: تحويل `ى` إلى `ي` (مثال: `مصطفى` يطابق `مصطفي`).
4. **إزالة التشكيل والتطويل**: تجاهل حركات التشكيل (`[\u064B-\u065F\u0670\u06D6-\u06ED]`) والتطويل (`ـ` `\u0640`).
5. **توحيد الأرقام**: تحويل الأرقام العربية المشرقية (`٠-٩`) والفارسية/الأردية (`۰-۹`) إلى أرقام ASCII (`0-9`) بحيث ينجح البحث بأي صيغة رقمية.
6. **توحيد المسافات والحروف اللاتينية**: تحويل الحروف الإنجليزية إلى lowercase وتقليص المسافات المتعددة.

## 4. منطق ترتيب النتائج والتمييز الآمن

### 4.1 ترتيب النتائج الحتمي (5 مستويات)
تُرتب النتائج تنازليًا وفق مستويات التطابق الخمسة التالية:
1. **تطابق تام في العنوان الأساسي (`exact` — الدرجة 1000)**: النص المطبّع للعنوان يساوي نص البحث تمامًا.
2. **تطابق في بداية العنوان (`prefix` — الدرجة 800..850)**: العنوان يبدأ بنص البحث.
3. **تطابق كلمة كاملة أو بداية كلمة في العنوان (`word` — الدرجة 600..650)**: إحدى كلمات العنوان تطابق نص البحث أو تبدأ به.
4. **تطابق جزئي داخل العنوان (`partial` — الدرجة 350..400)**: نص البحث يظهر كسلسلة فرعية داخل العنوان.
5. **تطابق في الحقول الثانوية أو المرتبطة (`related` — الدرجة 200..290)**: التطابق في الشركة، ملخص النقاش، القرارات، جدول الأعمال، اسم العميل المرتبط، الوسوم، أو الإجراء القادم.

عند تساوي الدرجة، يُحسم الترتيب حتميًا بـ: التاريخ الأحدث أولاً ← الترتيب الأبجدي للعنوان ← المعرف (`id`).

### 4.2 التمييز الآمن (`extractHighlightSegments`)
- يستخدم المحرك خريطة مواضع الحروف (`normalizeWithIndexMap`) لربط كل حرف في السلسلة المطبّعة بموضعه الحقيقي في النص الأصلي (حتى مع وجود تشكيل أو تطويل).
- يعيد مصفوفة قطع نصية صريحة `HighlightSegment[]` (`{ text, matched }`) تُرسم بواسطة عناصر React (`<mark>`) دون أي استخدام لـ `dangerouslySetInnerHTML`، مما يمنع ثغرات XSS أو HTML Injection تمامًا.

## 5. الفلاتر الذكية المدعومة

يدعم البحث الشامل الفلترة المنفردة والمركبة عبر:
1. **نوع السجل (`recordType`)**: الكل، عميل، جهة اتصال، فرصة عمل، اجتماع، مهمة، ملاحظة.
2. **العميل (`clientId`)**: تصفية جميع السجلات المرتبطة بعميل محدد.
3. **الفترة الزمنية (`datePreset`)**: كل الأوقات، اليوم، خلال 7 أيام، خلال 30 يومًا، خلال 90 يومًا، أو فترة مخصصة (`dateFrom` / `dateTo`).
4. **الحالة (`status`)**: حالات المهام، الاجتماعات، العملاء، ومراحل الفرص.
5. **الأولوية / الأهمية (`priority`)**: عاجل، مرتفع، متوسط، منخفض.
6. **الوسوم (`tag`)**: قائمة ديناميكية بجميع الوسوم المستخدمة في العملاء والملاحظات.
7. **حالة الفرص التجارية (`opportunityState`)**: جميع الفرص، الفرص المفتوحة فقط، الفرص المغلقة، الفرص المكسوبة (`won`)، أو الفرص الخاسرة (`lost`).

يمكن إزالة أي فلتر مفرد من شريط الشارات المفعّلة أو الضغط على **«مسح كل الفلاتر»** مع الاحتفاظ بنص البحث المكتوب.

## 6. بنية تصدير JSON وإصدار القالب `schemaVersion`

يُولّد `buildUserDataExportBundle` (`src/utils/dataPortability.ts`) ملف JSON قياسيًا يحمل الإصدار:

- `schemaVersion`: `"murafiq-export-v1"`
- `application`: `"Murafiq"`
- `exportedAt`: طابع زمني بصيغة ISO 8601
- `completeness`:
  - `status`: `"complete_online"` فقط عندما يكون المستخدم متصلاً بالإنترنت وجميع المجموعات الست محمّلة ولا توجد عمليات محلية معلقة.
  - `status`: `"partial_or_offline"` في حال عدم الاتصال أو عدم اكتمال تحميل إحدى المجموعات أو وجود كتابات محلية معلقة، مع تنبيه واضح بعدم اعتبار الملف نسخة سحابية مكتملة.
- `attachmentPolicyDisclosureAr`: النص الإلزامي الصريح حول عدم شمول ملفات Backblaze B2.
- `securityDisclosureAr`: تنبيه بأن الملف المصدّر غير مشفر تلقائيًا.
- `counts` و`data`: تشمل المجموعات المدعومة فقط (`clients`, `meetings`, `tasks`, `notes`, `opportunities`, `opportunityStageEvents`) الخاصة بالمستخدم الحالي بعد تجريد أي حقول سرية أو داخلية.

## 7. بنية تصدير CSV وحماية CSV Formula Injection

يدعم النظام تصدير 4 قوائم بصيغة CSV متوافقة مع Excel واللغة العربية:
1. **قائمة العملاء (`clients`)**
2. **قائمة فرص الأعمال (`opportunities`)**
3. **قائمة الاجتماعات (`meetings`)**
4. **قائمة المهام (`tasks`)**

### الضوابط التقنية والأمنية في CSV:
- **UTF-8 BOM (`\uFEFF`)**: يُضاف في مطلع كل ملف CSV لضمان قراءة الحروف العربية بشكل سليم في Microsoft Excel وLibreOffice Calc.
- **حماية CSV Formula Injection (`sanitizeCsvCell`)**: أي خلية تبدأ بـ `=` أو `+` أو `-` أو `@` أو محارف التحكم (`\t`، `\r`) — حتى لو سبقتها مسافات بيضاء — يتم تحييدها تلقائيًا بإضافة علامة اقتباس مفردة بادئة `'` لمنع تنفيذ المعادلات الخبيثة عند فتح الملف.
- **المعالجة القياسية (RFC 4180)**: إحاطة القيم التي تحتوي على فواصل أو علامات اقتباس مزدوجة أو أسطر متعددة بعلامات اقتباس مزدوجة مع مضاعفة علامات الاقتباس الداخلية `""`.
- **احترام تعدد العملات**: في تصدير الفرص، يُفصل عمود «القيمة التقديرية» عن عمود «العملة» (`JOD`, `SAR`, `USD`, إلخ) دون جمع عملات مختلفة في إجمالي واحد مضلل.

## 8. خطوات الاستيراد الآمن والقيود المفروضة

يعمل الاستيراد عبر 4 مراحل إلزامية داخل تبويب **«إدارة البيانات»** في الإعدادات:

1. **المرحلة 1 — اختيار الملف**:
   - يدعم ملفات تصدير «مُرافق» بصيغة JSON (`murafiq-export-v1` وكذلك الإصدار التمهيدي السابق `1.0.0-prototype`) أو قائمة عملاء بصيغة CSV.
   - الحد الأقصى لحجم الملف: **5 ميجابايت**.
   - لا يتم تنفيذ أي كتابة عند اختيار الملف.
2. **المرحلة 2 — التحقق الأمني وتطهير الحقول (`validateAndPreviewImport`)**:
   - فحص سلامة JSON/CSV وإصدار القالب.
   - حظر أي ملف يتضمن مفاتيح تلويث النموذج الأولي (`__proto__`, `constructor`, `prototype`).
   - التحقق من مطابقة جميع المعرفات للنمط الآمن `^[a-zA-Z0-9_\-]{1,128}$` ورفض أي مسارات نسبية أو محارف غير صالحة.
   - تطبيق قوائم الحقول المسموحة (`Allowed Keys Whitelist`) المطابقة لقواعد `firestore.rules` واستبعاد أي حقول غير معروفة أو مفاتيح مرفقات.
   - تجاهل أي `userId` وارد في الملف وربط جميع السجلات المستوردة بمعرف المستخدم المصادق عليه حاليًا (`user.uid`).
3. **المرحلة 3 — المعاينة التفصيلية قبل الاستيراد**:
   - عرض جدول إحصائي لكل كيان يوضح: إجمالي السجلات في الملف، السجلات الصالحة للاستيراد، السجلات المكررة (التي سيتم تخطيها)، السجلات المرفوضة، وتحذيرات العلاقات المرجعية المفقودة.
4. **المرحلة 4 — التأكيد الصريح والتنفيذ الآمن (`executeSafeImportPlan`)**:
   - يشترط تفعيل مربع التأكيد الصريح من المستخدم وأن يكون التطبيق متصلاً بالإنترنت (`isOnline === true`).
   - لا يوفر النظام أي خيار لحذف البيانات الحالية أو `Replace All` أو `Reset Database`.
   - تُكتب السجلات بترتيب طوبولوجي يحترم الاعتماديات: `clients` أولاً ← `opportunities` ← `meetings` ← `tasks` ← `notes` ← `opportunityStageEvents`.

## 9. سياسة التعامل مع التكرار والعلاقات المفقودة والفشل الجزئي

1. **السجلات المكررة (`DUPLICATE_SKIPPED`)**:
   - السياسة الافتراضية المعتمدة هي **تخطي السجلات المكررة (Skip Duplicates)** دون الكتابة فوق السجلات الحالية للمستخدم.
   - في استيراد CSV للعملاء، يتم كشف التكرار عبر معرف العميل (إن وجد) أو عبر المفتاح الطبيعي المطبّع (`الاسم + الشركة + الهاتف + البريد`).
2. **العلاقات المرجعية المفقودة**:
   - السجلات التي تشترط وجود عميل أب (`meetings`, `tasks`, `opportunities`) ويُشار فيها إلى `clientId` غير موجود لا في حساب المستخدم الحالي ولا ضمن دفعة العملاء الصالحة في الملف يتم استبعادها مع تحذير صريح (`MISSING_CLIENT_SKIPPED`) لمنع إنشاء سجلات يتيمة.
   - الروابط الاختيارية المفقودة (`note.clientId`, `meeting.opportunityId`, `task.meetingId`, `task.opportunityId`) يتم فك ارتباطها بأمان (`BROKEN_OPTIONAL_LINK_UNLINKED`) مع استيراد السجل نفسه وإبلاغ المستخدم في تقرير المعاينة.
3. **الفشل الجزئي وإعادة المحاولة الآمنة (`partial_failure`)**:
   - يتتبع المحرك مفاتيح السجلات التي نجح حفظها (`succeededRecordKeys`).
   - إذا فشل حفظ بعض السجلات أثناء التنفيذ، يعرض التقرير عدد السجلات الناجحة والفاشلة بدقة ويوفر زر **«إعادة محاولة السجلات الفاشلة فقط»** الذي يعيد إرسال السجلات المتعثرة فقط دون تكرار السجلات التي نجحت في المحاولة الأولى.

## 10. سياسة عدم شمول ملفات مرفقات Backblaze B2 في التصدير والاستيراد

- لا يقوم البحث الشامل بفهرسة أو تنزيل محتوى الملفات المخزنة في Backblaze B2.
- يتضمن كل ملف تصدير JSON وفي واجهة «إدارة البيانات» النص الإلزامي الصريح:
  > **«يتضمن هذا التصدير بيانات التطبيق المدعومة فقط، ولا يتضمن ملفات المرفقات المخزنة في Backblaze B2.»**
- عند التصدير أو الاستيراد، يتم تجريد أي حقول خاصة بالمرفقات السحابية (`storageKey`, `presignedUrl`, `downloadUrl`, `uploadIntents`, `_meetingGuard`, `photoPaths`) ولا يتم استدعاء أي نقطة نهاية خاصة بـ Backblaze B2.

## 11. القيود المعروفة في الإصدار الحالي

1. يبحث نظام «البحث الشامل» في السجلات النصية والمهيكلة المحمّلة ضمن جلسة المستخدم الحالية ولا يبحث داخل محتوى ملفات PDF أو الصور المرفقة.
2. يدعم الاستيراد بصيغة CSV استيراد قائمة العملاء (`clients_csv`)، بينما يتم استيراد منظومة السجلات الكاملة المترابطة عبر قالب JSON الموحد (`murafiq-export-v1`).
3. يتطلب تنفيذ الاستيراد اتصالاً نشطًا بالإنترنت لضمان التحقق الفوري من قبول الخادم لكل سجل.

## 12. الفرضيات التصميمية القابلة للمراجعة

1. **إدراج جهات الاتصال (`ClientContact`) كنوع سجل مستقل في نتائج البحث**: عند البحث عن اسم أو هاتف أو منصب جهة اتصال داخل العميل، يظهر السجل بشارة «جهة اتصال» مع اسم العميل الأم، وعند النقر عليه يفتح ملف العميل الشامل (Client 360) مباشرة.
2. **معامل الفلتر الزمني (`datePreset`)**: يعتمد في المقارنة على التاريخ التشغيلي الأهم لكل كيان (تاريخ الاجتماع للاجتماعات، تاريخ الاستحقاق للمهام، تاريخ الإجراء القادم/الإغلاق للفرص، وتاريخ آخر تحديث للعملاء والملاحظات).
3. **تنظيف جلسة الاستيراد المؤقتة**: تُحفظ بيانات معاينة الاستيراد في ذاكرة المكون (`useState`) فقط وتُمسح فور إغلاق النافذة أو تبديل المستخدم دون تخزينها في `localStorage` أو `IndexedDB`.
