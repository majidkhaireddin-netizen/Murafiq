**المشروع:** مُرافق (Murafiq)  
**الحالة:** مُنفّذ ومُحقّق (Build, TypeScript, Unit & Security Tests)

## 1. النظرة المعمارية والتدفق الآمن (Security & Data Flow Pipeline)

تم بناء ميزة تحليل المستندات والمرفقات فوق البنية القائمة لتخزين Backblaze B2 الخاص ومحرك Google Gemini الخادمي (`@google/genai`) دون إنشاء أي نظام تخزين موازٍ أو مجموعات Firestore جديدة، وبما يلتزم حرفياً بقاعدة:

> **AI Suggests — Human Reviews — Human Approves**

مسار الطلب الموثوق:
1. **المستخدم في الواجهة (Client):** يختار مرفقاً واحداً مكتمل الرفع من قائمة مرفقات اللقاء أو يضغط على زر «تحليل ذكي» بجانب المرفق.
2. **حاجز عدم الاتصال والصلاحية المحلية:** إذا كان المستخدم دون اتصال (`!isOnline`) أو كان المرفق غير مدعوم أو يتجاوز `10 MiB` أو قيد الحذف/غير مكتمل الرفع، تُمنع العملية فوراً قبل أي طلب شبكي.
3. **الموافقة الصريحة (Explicit Consent Modal):** تظهر نافذة «الموافقة على تحليل المرفق بالذكاء الاصطناعي» موضحةً اسم المرفق، نوعه، حجمه، اسم اللقاء، اختيار الوضع («تحليل شامل» أو «طرح سؤال محدد» لمرة واحدة)، وإقرار الخصوصية وعدم الحفظ التلقائي. **لا يُرسل أي طلب قبل نقر «أوافق، ابدأ التحليل».**
4. **طلب العميل (`src/services/documentAi.ts`):** يرسل `POST /api/ai/document-analysis` متضمناً `Authorization: Bearer <Firebase ID Token>` وحقول الهوية والوضع فقط (`{ meetingId, attachmentId, analysisMode, question? }`). يُمنع إرسال `uid` أو `storageKey` أو روابط التحميل أو بايتات الملف.
5. **بوابة الخادم (`src/server/documentAiRouter.ts`):**
   - تتحقق من `Firebase ID Token` وتستخرج `uid` حصراً من الرمز الموثوق.
   - ترفض أي حقول تزوير مثل `uid` / `storageKey` / `downloadUrl` / `bytes` برمز `403 FORBIDDEN`.
   - تتحقق من ملكية اللقاء والمرفق في قاعدة البيانات المسماة (`ai-studio-murafiq-cb988db3-5a07-40b7-b1ca-8eaaae894475`).
   - ترفض المرفقات المحذوفة أو قيد الحذف (`410`)، غير المكتملة (`409`)، المخالفة لمسار العزل `users/{uid}/meetings/{meetingId}/attachments/{attachmentId}` (`403`)، الصيغ غير المدعومة (`415`)، أو الأحجام > `10 MiB` (`413`).
   - تطبّق حدود المعدل (`5` طلبات/دقيقة لكل `uid` -> `429`) وقفل منع الطلبات المتزامنة المكررة لنفس المرفق (`409`).
   - تجلب بايتات الملف خادمياً من Backblaze B2 عبر `storage.downloadObject(expectedKey)` وتتحقق من الحجم الفعلي ومن البصمة الثنائية (`verifyMagicBytes` -> `422` عند الاختلاف).
6. **محرك Gemini (`src/server/geminiDocumentAssistant.ts`):**
   - يستخدم `@google/genai` عبر الخادم فقط (`GEMINI_API_KEY` خادمي حصراً، والنموذج الافتراضي `gemini-4-hydrogen` قابل للتخصيص عبر `GEMINI_DOCUMENT_MODEL`).
   - يمرّر بيانات الملف كـ `inlineData` ومهلة تنفيذ `45s` مع دعم `AbortSignal` وإرشادات صارمة لعزل محتوى المستند و`<USER_QUESTION>` عن الأوامر (Prompt Injection Resistance).
   - يفرض `responseMimeType: 'application/json'` و`responseSchema` محكمين، ثم يعيد التطبيع عبر `validateAndNormalizeDocumentAiResult`.

## 2. أوضاع التحليل والتخزين المؤقت في الذاكرة (RAM-Only)

- **الوضع الشامل (`comprehensive`):** يستخرج ملخص المستند (نوع المستند + الموضوع + نظرة عامة + `insufficientInfo`)، أبرز النقاط، القرارات المقترحة (`explicit` vs `needs_confirmation`)، المهام المقترحة، التواريخ والمواعيد المهمة، الأسئلة المفتوحة والمخاطر، والقيود/التنبيهات.
- **وضع السؤال المحدد (`question`):** طلب مستقل لمرة واحدة (بدون سجل دردشة محفوظ) يعيد إجابة مباشرة، قائمة `supportingEvidence`، مؤشر `insufficientInformation` الصريح عند نقص الدليل، و`limitations`.
- **خصوصية ذاكرة الجلسة (RAM-Only):** نتائج التحليل تحيا في React `useState` فقط؛ ولا تُكتب إطلاقاً في `localStorage` أو `sessionStorage` أو `IndexedDB` أو Firestore أو السجلات. تُمسح تلقائياً عند تغيير اللقاء، حذف المرفق، تغيير المرفق المحدد، أو الضغط على «مسح النتائج».

## 3. الاعتماد البشري، حماية المحضر النهائي، ووضع عدم الاتصال

- **لا حفظ تلقائي:** كل قسم يتطلب إجراءً يدوياً صريحاً من المستخدم.
- **حماية `meeting.notes`:** عند إضافة الملخص أو استبداله داخل `discussionSummary` (مع خطوة تأكيد صريحة قبل الاستبدال)، تبقى الملاحظات النصية القديمة `meeting.notes` مصونة بالكامل.
- **حماية المحضر النهائي (`minutesStatus === 'final'`):** يُحظر تعديل `discussionSummary` أو إضافة قرارات أو اعتماد موعد متابعة داخل المحضر مع توفير زر «إعادة فتح المحضر»، بينما تظل المهام المرتبطة المستقلة متاحة للإنشاء.
- **المهام ومنع التكرار:** يستخدم الاعتماد دالة `findDuplicateMeetingTask` و`approveSuggestedTasksSequentially`؛ وفي الاعتماد الجماعي لا تعيد المحاولة تكرار المهام التي نجح حفظها مسبقاً.
- **التواريخ والأسئلة المفتوحة:** التواريخ المهمة للعرض ما لم يعتمدها المستخدم كموعد متابعة (`applyAiFollowUpDateToMeeting`)، والأسئلة المفتوحة والمخاطر للمراجعة والتجاهل فقط ولا تتحول تلقائياً لمهام أو قرارات.
